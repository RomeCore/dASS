# Chat-level sub-agent tool policies

Status: resolved
Type: grilling
Blocked by:

## Question

Design the **chat-level sub-agent tool policies** that sub-agent tasks are launched with.

Background: a sub-agent task needs `AutoApproveBehaviours` / `DisallowedBehaviours`, but the only current source is the *calling chat agent's* settings. Sub-agent launches (`agent-callsub`, and the new `/agent:<name>` command — ticket 04) need a **chat-level** source instead.

Cover:

- which flags to add to `ChatSubAgentSettings` (currently an empty `ChatSettingsCategoryBase`, route `Chat.Settings.SubAgents`) — mirror the agent-level tool-policy settings?
- inheritance (app → chat) and defaults / migration;
- how `agent-callsub` (`AgentSubAgentTools`) and `ISubAgentTaskParamsResolver` obtain them instead of the caller's settings;
- UI surface for the settings.

## Answer

Elementary — reuse the existing policy-mask machinery:

- `ChatSubAgentSettings` (route `Chat.Settings.SubAgents`) gains a `ToolPolicyMask Policy` property marked **`[InheritedChatSetting]`** (app → chat inheritance). It becomes the chat-level source of `AutoApproveBehaviours` / `DisallowedBehaviours` for **every** sub-agent task.
- The three-state semantics are exactly `ToolPolicyMask`'s: a `ToolBehaviour` flag may be **auto-approve**, **disallowed**, or **ask** (neither flag).
- Consumers:
  - the `/agent:<name>` command executor (ticket 04) passes this policy into its `AgentTaskLaunchParameters`;
  - `agent-callsub` (`AgentSubAgentTools`) is reworked to read this chat-level policy **instead of** the calling chat agent's settings.
- UI mirrors the **BEHAVIOUR POLICY** section of `AgentToolSettingsView` / `AgentToolSettingsViewModel`:
  - `PolicyMaskCategoryItems` built from `ToolBehaviours.ByCategory` with `ToolBehaviourMaskItem`s (via `ToolBehaviourFlagInfo.Create`), tristate toggles driven by `ISetPolicyMaskFlag.SetPolicyMaskFlag(flag, bool?)`;
  - state mapping exactly as `GetPolicyMaskState` (auto-approve → true, disallowed → false, else null) and `SetPolicyMaskFlag`;
  - the effective mask is read/written through the generated `GetEffectivePolicy(chatSettings)` / `SetEffectivePolicy(chatSettings, mask)`.

No new concepts — just the chat-level instance of the existing tool-policy mask.
