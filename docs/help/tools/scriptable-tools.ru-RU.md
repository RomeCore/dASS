# Скриптовые тулы

**Скриптовый тул** - это тул, заданный файлом, а не кодом: фронтматтер файла - контракт, который читает модель, а
тело - реализация. Тот же формат файла даёт слэш-команды и prompt-контексты; меняется только папка.

## Что принимается

Тул - это один файл в папке `tools/` аддон-пака. Расширение выбирает движок:

| Расширение | Движок | Что нужно |
|---|---|---|
| `.lua`, `.alua` | AsyncLua | ничего - работает внутри процесса в любой сборке |
| `.py` | Python | сборка Desktop и Python (интерпретатор или виртуальное окружение) |
| `.sh` | Bash | сборка Desktop и bash (на Windows - Git Bash) |
| `.ps1` | PowerShell | сборка Desktop и `pwsh` 7 либо Windows PowerShell 5.1 |
| `.bat`, `.cmd` | Batch | Windows |

## Где живут файлы

Скриптовые тулы - обычные аддоны, поэтому лежат в аддон-паке рядом с остальными видами:

- папка `tools/` в аддон-источниках репозитория (например `.agents/packs/<pack>/tools/`);
- `%LOCALAPPDATA%\.llmassist\packs\<pack>\tools\` для паков, установленных на этой машине;
- папки паков, перечисленные в настройках приложения.

Регистрировать ничего не нужно: положите файл в сканируемую папку `tools/`, и после перезагрузки аддонов тул появится
в каталоге.

## Как написать

```yaml
--[[
title: Count files
description: Считает записи в папке и сообщает, сколько их.
category: Filesystem
argument-schema: |
  {"type":"object","properties":{"path":{"type":"string"}},"required":["path"]}
behaviours:
  - directory-read
--]]
print(#fs.list(tool_args.path))
```

Полный контракт - все ключи фронтматтера, что получает тело и как вид аддона сообщает результат - на странице
[Скриптование](scripting.md).

> [!TIP]
> `argument-schema` обязана быть **YAML-строкой** (`|`-блок или строка в кавычках). Однострочный маппинг `{...}`
> строкой не является, поэтому тул молча останется с пустой схемой и модели будет нечего заполнять.

См. также: [Тулы](../tools.md), [Скриптование](scripting.md).
