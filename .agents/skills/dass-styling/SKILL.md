# Styling inside dASS

One rule carries the whole system: **read roles, write roles.** A view names what a surface *is* (`CardBackground`, `TextSecondary`, `BorderSubtle`), never which shade of which ramp it happens to be. The ramp is an implementation detail; a view that reaches for `Neutral900` is a view that breaks the next time the palette is regenerated.

This skill is the vocabulary. The mechanics of getting a payload onto the screen are in `lua-ui-controls`; the shape of a tool or a context addon is in `tool-authoring` and `context-authoring`.

## Colour

### Roles

Every key below is a `SolidColorBrush` and resolves per theme variant. Both columns are the same role in light and dark - that is the point.

| Group | Keys | Reads as |
|---|---|---|
| Surfaces | `WindowBackground`, `PanelBackground`, `CardBackground`, `PopupBackground`, `Scrim` | window < panel < card; `Scrim` is the light-dismiss wash |
| Text | `TextPrimary`, `TextSecondary`, `TextTertiary`, `TextDisabled` | body, supporting, hint, off |
| Lines | `BorderSubtle`, `BorderDefault`, `BorderStrong` | hairline, field edge, hovered edge |
| Controls | `ControlBackground`, `ControlBackgroundHover`, `ControlBackgroundPressed`, `ControlBackgroundDisabled`, `ControlTrack` | the field/button surface ladder |
| Focus and selection | `FocusRing`, `SelectionBackground`, `SelectionForeground` | focus edge, selected wash |
| Primary | `PrimaryBase`, `PrimaryHover`, `PrimaryPressed`, `PrimarySubtle`, `PrimaryBorder`, `TextOnPrimary` | the one accent that means "action" |
| Accent | `AccentBase`, `AccentHover`, `AccentPressed`, `AccentSubtle`, `AccentBorder`, `TextOnAccent` | the second, decorative family |
| Status | a quartet per family (`Success`, `Warning`, `Error`, `Danger`, `Info`): `StatusSuccessBase`, `StatusSuccessSubtle`, `StatusSuccessBorder`, `TextOnSuccess` | subtle = wash, border = edge, base = ink and icon, `TextOn*` = text on the base |

Rules that are not obvious:

- **`DynamicResource`, never `StaticResource`.** A static reference freezes the brush of the variant that happened to be active when the view was built; the theme switch then half-applies.
- **Hover is darker in light and lighter in dark.** Never compute a hover shade from a base - use `PrimaryHover`, `ControlBackgroundHover`.
- **Elevation is a surface change, not a shadow.** A card on a panel is `CardBackground` on `PanelBackground`. Shadows are only for things that float over content (`composerCard`, a tooltip, a popup) and are written as a fixed translucent black, because a shadow that flips with the theme looks wrong in both.
- **A translucent wash over content is a role, not an alpha tweak.** `SelectionBackground` and `Status*Subtle` already carry their alpha.

### Rungs

Generated by `PaletteProvider`, the same for both variants on demand: `Neutral0 … Neutral1000`, `Primary0 … Primary1000`, `Accent0 … Accent1000` (step 50, then 100-900 by 100, then 950, 1000), plus per status family `Status<Name>500`, `Status<Name>Overlay`, `Status<Name>Line`, `Status<Name>On`.

Each colour is published twice: the key holds a `Color` (`Neutral900`), and `<Key>Brush` holds an `ImmutableSolidColorBrush`. `PrimaryOn` and `AccentOn` are the contrast-picked text colours behind `TextOnPrimary` / `TextOnAccent`.

Use a rung only when no role says what you mean - a one-off tint in a widget the palette does not describe - and say why in a comment.

### Colours outside the palette

`Styles/Resources/Colors.axaml` holds the two families that deliberately do not follow the theme: the terminal card (`TerminalBackground`, `TerminalForeground`, `TerminalBar*`) and the slash-command highlight (`SlashCommand*Brush`). A payload that renders a terminal uses these, not `Neutral1000`.

## Type

`FontSizeXs`, `S`, `M` (body, 14 by default), `L`, `Xl`, `2Xl`, `3Xl`, with a matching `LineHeight*` step. The scale is generated from a profile plus an accessibility multiplier, so a hardcoded `FontSize="16"` is a size that stops following the user's setting.

Weights in use: `Regular` (body), `Medium` (a selected or actionable label), `SemiBold` (a title), `Bold` (a count or a badge).

Sizes that are part of a control's own chrome - the 14 px icon in a chip - may be written literally; sizes that are read as text may not.

## Radii

`RadiusNone`, `RadiusS` (0.5×), `RadiusM` (1×, the base), `RadiusL` (1.5×), `RadiusXl` (2×), `RadiusPill` (9999). Directional forms exist for each size: `RadiusTopM`, `RadiusRightM`, `RadiusBottomM`, `RadiusLeftM`. `RadiusInnerM` (and `S`, `L`, `Xl`) is the radius for a surface nested inside a `Radius…` parent - it keeps the corners concentric instead of visibly parallel.

`8,0,0,8` is never correct: it is `RadiusLeftM` written in a way that ignores the user's radius base.

## Spacing and metrics

`SpacingXs` 2, `SpacingS` 4, `SpacingM` 8, `SpacingL` 12, `SpacingXl` 16, `Spacing2Xl` 24 - for `Spacing`, `Margin`, `Padding` and `RowSpacing` of stacks and grids.

`PaddingXs` 4,2, `PaddingS` 8,4, `PaddingM` 12,6, `PaddingL` 16,8, `PaddingXl` 24,12 as `Thickness` resources.

`BorderThickness` 1 and `BorderThicknessThick` 2. `ControlHeightXs` 18, `ControlHeightS` 24, `ControlHeightM` 32, `ControlHeightL` 40 - the ladder the icon classes size themselves from.

`DurationFast` 180 ms, `DurationNormal` 300 ms, `DurationSlow` 480 ms; easings `EasingStandard` (`CubicEaseInOut`) and `EasingOut` (`CubicEaseOut`).

## Built-in controls

| Control | Namespace | What it is | Properties worth knowing |
|---|---|---|---|
| `SmoothScrollViewer` | `LLMDesktopAssistant.Controls.Scrolling` | Animated scrolling; the app's default scroll surface, USE IT INSTEAD OF DEFAULT ScrollViewer | `Step` 50 (px per wheel notch), `Duration` 180 ms, `MaxSpeed` 10000, `FollowEnd` (stick to the bottom while content grows - the message list), `IsFollowingEnd` (read-only), `AnimateTo(y)`, `AnimateToEnd()` |
| `MarkdownControl` | `LLMDesktopAssistant.Controls` | Renders markdown with code blocks, alerts and the selection toolbar | `MarkdownText`, `UsePlaintext` (the switch between rendering MarkdownText as plain text or not, default - false, renders Markdown), `OpenLink`, `ImageBasePath`, `AnimateBlocks`; `SelectionProcessorsProvider` and the code-block providers stay `null` in a payload (they need chat services) |
| `ProgressRing` | `LLMDesktopAssistant.Controls` | Indeterminate or determinate ring, 24 px by default | `Value`, `Minimum`, `Maximum`, `IsIndeterminate`, `StrokeThickness`; colours through `Foreground` (defaults to `PrimaryBase`) |
| `VisualIcon` | `LLMDesktopAssistant.Controls.Icons` | Monochrome tintable glyph, sized by `FontSize` or `Width`/`Height` | `Kind` (`material:Name`, a bare `Name` means material, `path:M12 2 …`), `Material`, `Path`; invalid data renders red with a tooltip |
| `HighlightTextBox` | `LLMDesktopAssistant.Controls.Text` | The chat input: a text box with a highlight transform provider | `Text`, `PlaceholderText`, `UseFloatingPlaceholder` (the caption above the text, where the hotkeys live), `HighlightTransformProvider`; `Classes="nochrome"` for a field whose host draws the frame |

Everything else is stock Avalonia, already themed: `Button`, `ToggleButton`, `ComboBox`, `TextBox`, `CheckBox`, `Slider`, `ProgressBar`, `ListBox`, `TreeView`, `Expander`, `TabControl`, `Menu`, `ToolTip`, `ScrollBar`, `GridSplitter`. Build the payload out of these and it inherits the theme for free.

## Style classes

### Buttons

| Class | Applies to | Effect |
|---|---|---|
| `icon` | `Button`, `ToggleButton`, `RepeatButton` | frameless, 32×32, icon 24, `TextSecondary` → `TextPrimary` on hover |
| `icon small` | same | 24×24, icon 16 |
| `icon mini` | same | 18×18, icon 14 |
| `icon large` | same | 40×40, icon 32 |
| `ghost` | `Button`, `RepeatButton` | no frame, muted text; for a text action in a toolbar |
| `accent` | `Button`, `RepeatButton` | `PrimaryBase` fill with `TextOnPrimary` |
| `danger` | `Button`, `RepeatButton` | `StatusDangerSubtle` fill, `StatusDangerBase` ink |
| `solid` | `ToggleButton` | checked = `PrimaryBase` fill |
| `segment` | `ToggleButton` | a segment of a segmented strip: checked = `CardBackground` + shadow |
| `floatingAction` | `Button` | 44 px pill on `CardBackground`, for a control over the conversation |
| `tabLabel` | `Button` | the label half of a chat tab |
| `chipLabel` | `Button` | the label half of an input chip |

`BoxShadow` does not exist on a `Button`: a pill that needs a shadow is a `Border` with a shadow holding the button, or it goes without one.

### Fields

| Class | Applies to | Effect |
|---|---|---|
| `nochrome` | `HighlightTextBox`, `TextBox` | no background, no border, no focus frame - the host owns the frame (keeps the floating placeholder) |
| `flat` | `ComboBox` | no frame, transparent: one segment of a host-drawn pill, the host draws border and radius |
| `icon` | `ComboBox` | read as an action: 32×32, frameless, no chevron, icon only |

### Lines and surfaces

`Separator`: `flush` (no margin, the parent spaces), `vertical` (1 px, stretches - the seam between toolbar groups), `section` (wider margin).

Chat surfaces, from `Styles/Custom/Chat.axaml`: `Border.composerCard`, `Border.chatHeader`, `Border.chatTabStrip` + `Border.chatTab(.active)` + `Button.tabLabel`, `Border.countBadge` (a count on a header action, a sibling of the button, never its content), `Border.inputChip(.accent)` + `Button.chipLabel`, `Button.floatingAction`, `Border.chatSidePanel`, `Border.MessageBubble`, `Border.messagePartChip`.

## Chat surfaces

All four are `dass.chat.append_data(handle, options)`; the surface is the host's wrapper, the payload is your control.

| `surface` | Where it lands | What the host draws | What the payload must be |
|---|---|---|---|
| `"rail"` with `horizontal` / `vertical` | a strip inside the composer card, above or below the input, left or right group | the hairlines between items - never add your own separator | one compact control, `VerticalAlignment="Center"`, ~20-24 px tall: an icon button (`Classes="icon small"`) or a pill (`Border` on `ControlBackground`, `RadiusPill`, `Padding="8,2"`) |
| `"tab"` with `title`, `icon`, `closeable` | the strip under the chat header; its content covers the conversation and the composer | the tab itself (underline, title, icon, close), the strip, the scroll surface | a page: a title block, then cards. `Margin` is the host's, so start at `0`. One tab is open at a time; clicking the open tab returns to the chat |
| *(none)* | the side panel on the right, 320 px by default | `PanelBackground`, the left hairline, `Padding=16`, 12 between items | a self-contained card: `CardBackground` + `BorderSubtle` + `RadiusM` + `Padding="12,10"`. The panel draws no frame per item |
| `"overlay"` with `title`, `icon`, `left`/`top`/`width`/`height` (fractions 0..1), `closeable` | a floating window over the conversation | the window frame, the header (icon, title, collapse, fit, tray, close) and the same row in the tray, the scroll body | the body only - no border, no title, no icon of your own |

```lua
dass.chat.append_data(ui, {
    surface = "tab",
    title = "Токены",
    icon = "ChartTimeline",     -- a material icon name
    closeable = true,
    replacement_key = "my-addon:tokens",
})
```

- A chip in a message is `dass.chat.append_part{ title = "…", icon = "…", color = "#RRGGBB" }` - there the *host* draws the pill, so the payload is text only.
- `replacement_key` is what makes an update an update: re-appending under the same key replaces the item and keeps what the user chose (an open tab, a window's place).
- `visible = false` removes the item from its surface without detaching it. `temporary = true` keeps it out of the database.
- Rail and side-panel items have no close button of the host - a payload that must be dismissible needs its own control for it.

## Dynamic payload checklist

- The root element declares `xmlns="https://github.com/avaloniaui"` and one `xmlns:` per type namespace used. Without the first nothing resolves and the control renders as an error box.
- Bindings are reflection bindings: `{Binding key}`, no `x:DataType`, no `{CompiledBinding}`, and no `x:CompileBindings="True"`.
- The view model is a Lua table; write through `vm:set(key, value)` - a plain assignment stays frozen until `vm:notify`.
- An array renders a list (`ItemsSource`), a dictionary does not.
- A command is `function(self, param)` or `function vm:name()`; the dotted *statement* form crashes the parser.
- A long string holding markup uses `[==[ … ]==]`; a `]]` inside ends a plain `[[ ]]` early, and the half-written XAML fails at render time with a message about the character.
- A render failure is silent in the tool result: the chat shows "Failed to render dynamic UI" and the script keeps running. Check the visual, not the return value.
- Use `IsVisible`, not `Opacity="0"`, to take something out of the layout.

## Checking your work

Render it (`lua-execute` is itself a tool), then look at the two things that silently break: **both variants** (switch the theme - a role key looks right in one and can be invisible in the other) and **the narrow window** (a rail chip and a toolbar action are the first things to collide).
